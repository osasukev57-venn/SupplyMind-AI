# 人工 / 文件导入历史回填闭环（RC12）

修复 RC11 中人工来源的“运行 / 重试”始终返回等待，以及旧刷新方法用同月任意一条发布记录判定整段范围完成的问题。已有 raw、生命周期、历史报告和配置不删除、不伪造发布状态。

## 录制时怎么演示

1. 在动态配置页为已配置的监测项创建历史回填任务，指定起止日期。
2. 点击“运行”，系统核对该监测项在请求范围内的已发布数据，列出尚缺日期。
3. 在“来源与录入”页输入同一监测项编号、实际来源、业务日期、数值及配置一致的单位。材料示例单位是“元/吨”，不是币种 CNY。
4. “提交录入”只受理到 PENDING；再点击“校验并发布到面板”。文件导入则上传后点击“批量校验并发布到面板”。
5. 发布成功后，后端自动重新核对包含该业务日期的关联任务。回到动态配置页查看，必要时点击“刷新任务”。无需重建任务。
6. 部分日期发布后显示“部分完成”，并逐条列出仍缺日期。补齐后自动显示“已完成”，清除已解决的等待说明。
7. 对旧版遗留等待任务，点击“运行”或“重试”，会重新核对已经发布的数据。不要重复录入同一天来强行推进任务。
8. 完成后重复运行 / 重试不会重新录入或发布数据。关闭应用再启动，任务状态仍保留。

## 本轮截图的日期要求

监测项：`MAT.AZ91D.VIDEO28_MANUAL`；范围：`2026-10-23` 至 `2026-10-28`。

当前业务日历 `weekday-asia-shanghai-v1` 按周一至周五检查，因此必需日期是：

- 2026-10-23
- 2026-10-26
- 2026-10-27
- 2026-10-28

24、25 日为周末，不要求虚构数据。该日历不是完整法定节假日 / 调休交易日历；任务按创建时的配置快照核对，不因之后的日历配置改变而悄悄扩大或缩小要求。

只录入其中一日不代表整个范围完成；同月但范围外的数据、其他监测项、PENDING、REJECTED、CONFLICT 和 DEMO 数据不算补齐。已发布且通过校验的 VERIFIED 与 VERIFIED_WITH_NOTICE 数据均可计入，证据完整性损坏则不能据此宣告成功。

“检查点”表示连续核对覆盖到的日期，遇到缺口不会跳过。周末无需补录，所以检查点可能覆盖到周末。“已完成范围月份”仅表示该月落在本任务范围内的必需日期已补齐，不是整月行情完整。

## 升级注意

请使用 RC12 修复包；仍打开的 RC11 窗口不会自动加载新代码。迁移时保留原 data 文件夹，本轮准备的继续录制副本只复制原数据，不添加验收模拟数据。隔离接口验收数据位于单独的 `target/backfill-loop-rc12-http-data`，不要用于视频录制。

若发布成功但任务进度更新出现存储异常，来源页会明确提示“数据已发布，但回填任务进度更新失败”，可回到任务中运行 / 重试核对，不能把已发布数据误报为录入拒绝。

本次不改动云模型提示词、采用校验或调用重试策略，不额外调用真实云模型。浏览器验证连接在本轮不可用，验证范围以实际保存的后端、前端测试及打包接口结果为准。

已知独立限制：本轮额外验收发现，过长的监测项编号会让原有存储层拼接出的单段临时文件名过长，导致文件导入失败。诊断使用的 `MAT.AZ91D.BACKFILL_IMPORT_TEST` 触发了该限制；视频现用 `MAT.AZ91D.VIDEO28_IMPORT` 不属于该超长测试编号。本次不改动底层临时文件命名与崩溃恢复协议；先保留错误证据，单独处理该限制，不能把这个失败记作导入闭环通过。
