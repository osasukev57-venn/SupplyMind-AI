# Agent V3 定向修复与成品化候选自审

实施基线：`2a26ea9016f5014e9d0fe9be5e5d964f2dced88f`，分支 `codex/business-loop-fixes`。本文件记录本地自审，不是独立审查 PASS 或最终交付证明。最终候选、包摘要及本次实测结果以独立证据目录的交接报告为准。

## 范围与根因

用户批准的两个目标一起实施：聚合行级证据绑定，以及 `AGENT-V2-DELIVERY-DESIGN.md` 中的分段解读、部分采用、输入和页面呈现。保留前一候选的月均同义词、当前预警选择、确认绑定和安全诊断修复。

原实际数据中，同一月度文件的 VERIFIED 组配置版本为 `[5,12]`，VERIFIED_WITH_NOTICE 组为 `[5]`。旧 V1 文件级标量 lineage 无法忠实表达此异构性，严格拒绝有其合同依据；不能合并配置版本、采用首行或重导入数据绕开。新证据版本在文件 SHA/manifest 之上增加逐行身份与摘要，再与每个 Fact 绑定。原 CSV、业务值、计算、发布规则不变。

旧 answerTemplate 的全文占位符约束不能满足正常中文解释和独立段落采用。本批移除该生产分支，改用 sections/recommendations DTO、Spring AI 1.1.8 BeanOutputConverter 和 JSON_OBJECT。模型输出先结构检查，再按事实角色检查；Java 事实卡片与模型解读分开，不能将结构检查描述为任意自然语言语义证明。旧请求的具体 INVALID_FACT_TEMPLATE 分支缺少原始模型正文，无法事后重建；新路径提供受控拒绝码，不输出被拒模型正文。

## 调用链及兼容

`QueryPlanner → 现有只读工具 → 文件/manifest/真实聚合行验证 → 精简 AnalysisContext → 有界模型端口 → NarrativeValidator → 原有证据快照闭包 → V3 报告原子提交 → 页面/严格重读`。

新版本明确为 `AGENT-EVIDENCE-SCHEMA-V2`、`AGGREGATE-ROW-EVIDENCE-V1` 和 `AGENT-REPORT-V3`，规范见 `data-dictionary/AGENT-EVIDENCE-SCHEMA-V2.md`、DEC-071/072。旧 V1/V2 报告保持原严格读取，不迁移或重写，不回退到最新统计。

完整既有分组身份包含监测项、来源/访问方式/指纹、spec、周期、校验状态及版本、计算精度/舍入与版本、日历版本、币种/单位。configVersions 属于各行 lineage，不合并。规范行摘要从真实解码行经冻结 CSV 编码生成，完整字节另由文件 SHA 绑定。黄金向量由独立 Python 算法从原 CSV 生成，防止仅以实现自身证明自身。

V3 复用准确原字节快照、manifest、originalRef 身份和必要依赖闭包；对每个 Fact 重建行绑定。报告是最后可见入口。原子提交不被强杀，失败可能留下孤立快照，但不会把未持久化结果报告为已保存。512 文件/32 MiB 上限、无自动垃圾回收保持不变。

模型 FULL/PARTIAL/NONE 与持久化 generatedBy/degraded 必须一致。V3 重读重新校验采用段、引用与关键业务主张。严重秘密/注入或坏 JSON 整体拒绝；结构有效后独立坏段不影响其他合格段，建议仅依赖已采用事实。原 DEMO、损坏证据、错误引用、无依据数值和风险解除断言仍拒绝。

当前预警仍由 Java 按请求范围、最新业务日期及适用规则版本筛选。确认只表示知悉，不改变风险。历史预警保留。页面固定说明模拟性质、生成时事实、实际范围、各组样本截至日和周期不完整；预警的价格校验状态显示不适用。保存报告可按标识重新核验打开，不调用模型。

## 预算、资源与边界

沿用同一 System.nanoTime 请求预算：只读阶段截止 30 秒，云阶段截止 75 秒，85 秒为报告提交准入，客户端 90 秒。阶段不重新获得完整预算；最多一次模型端口调用，不做内容修复或网络重试。输出最多 2200 token；上下文最多 20000 字符、8 个均值组，问题最多 2000 字符。超限不调用模型，保留本地事实。

有限的两个工作线程、零排队、协作取消和迟到结果无持久化入口保持不变。已进入安全原子提交的工作允许完成；不强杀写盘。90 秒是正常支持环境目标；受控正常场景若超出仍是缺陷，不能用 OS 卡死边界掩盖。
