实施基线为 `c337e1f56d56fb3540d3f252800f05fdc865307f`，分支 `codex/business-loop-fixes`。本文件是实现和自审说明，不是独立审查PASS或最终交付证明。唯一最终候选及运行包摘要以本轮证据交接报告为准。

## 已知事实与根因

`docs/evidence/agent-real-cloud-20261026/RESULT.md`、`01-latest.response.json`与`01-latest.report-read.json`记录了一次真实qwen-plus请求：HTTP200、21973ms、PARTIAL。API已经接通，不按配置失败处理。

已采用的QUALITY段末句是“全部事实均经VERIFIED校验”。原范围实际有4条VERIFIED和4条VERIFIED_WITH_NOTICE。旧投影把派生质量指标的validationStatus与底层样本状态放在同一通用字段，且验证器只核对指标数值/引用，未阻断从指标到全体样本状态的错误推广。派生质量事实继承了来源元数据，不能将这个兼容字段当作全体样本的业务校验结论。

此外，生产提示词泛化邀请五种主题和最多四条建议，原请求的theme未传到云端解释请求；只读工具返回了质量和趋势事实，并不意味着用户要求云端解释所有事实。已被拒段没有原文，不能由UNSUPPORTED_NUMBER或WRONG_FACT_ROLE推测具体内容，更不能笼统判为误拦。

## 修改及兼容边界

- Java从完整、已核验的history.query事实构建独立sampleValidation分布，按监测项保留状态计数。该汇总在历史示例截断为两条之前完成，不依赖模型计算或派生指标的状态标签。
- 云端quality角色不再暴露通用validationStatus，而显示派生指标的证据核验/Java计算含义。原EvidencePack、CSV及报告合同字段不重写，不修改业务计算、校验或发布规则。
- NarrativeValidator对真实混合样本的全体状态概括、派生指标/样本状态混淆和错误状态计数失败关闭。支持正常中文、大小写等义标签、合法混合/存在性说明；不是白名单固定句子。指标完整率100%不能证明全体样本VERIFIED。真实均一VERIFIED群体仍可如实陈述。
- 新请求由Java结合问题和主题确定NarrativeScope，传入云端投影及采用校验。最新值窄问题只投影最新值角色，不邀请额外趋势/质量/预警；未请求建议时上限0，明确请求时至多1条。合法主题和角色之外的段落返回受控OUT_OF_REQUEST_SCOPE，保留独立正确段落。
- FULL/PARTIAL/NONE、正常中文、事实引用、未知factId/数字/单位/来源/风险/确认等既有拒绝能力保留。无内容修复或新增云请求；预算/并发/取消合同不变。
- 页面质量事实详情明确标为“派生质量指标（证据已核验，不代表样本校验状态）”，底层样本的各自状态继续显示。

不增加持久化模型版本、不迁移或重写旧文件。旧V3没有持久化请求theme，重读不伪造历史theme，也不追溯套用新请求的输出数量限制；仍执行完整性、引用和加强后的语义检查。含本次错误QUALITY的旧报告会返回不可验证（409），原件保留；其他合法旧报告按原严格入口读取。

本检查仍是结构、引用和关键主张的有界语义检查，不宣称证明任意自然语言绝对正确。
