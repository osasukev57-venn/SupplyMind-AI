# SupplyMind Agent 成品化改造方案

日期：2026-10-25。状态：设计建议与实施边界，不代表已完成或已通过验收。

## 目标与基线

以 v0.9.0 已有业务能力和当前业务闭环修复为基础，交付能够读取实际业务数据、生成可读云端分析、解释预警及确认状态的 Windows 运行版本。实现时从当前已核对的修复候选继续，不退回旧版本丢弃修复。v0.9.0、用户运行数据与已有验收材料保留。

当前 HEAD 为 15a70c7，工作区存在另一执行窗口未提交的 Agent 改动。它们是用户工作，实施前应逐项核对、保留有用修复并形成明确基线，不得 reset、覆盖或混入不明内容。本文仅新增设计文件，不修改生产代码。

本批范围是 Agent 的输入、事实整理、云端输出、检查、页面与报告持久化。采集、校验、发布、统计公式、预警阈值及确认合同不重新设计。既有模块仍需在最终运行包中完成必要冒烟，不因历史验收通过而免除当前版本集成验证。

## 已确认的问题

1. 原始问题使用“月度均值”却没有执行 period.metrics，说明关键词路由与事实就绪检查不一致。
2. 风险摘要曾直接选择第一条历史预警，显示23000→24900，未选择最新适用规则对应的23250→25500。
3. answerTemplate 要求每个 factId 恰好出现一次，正文不得独立出现数字、单位、来源等，容易将合理自然语言整体拒绝。
4. 一处错误触发整篇降级，用户只看到 Java 模板，不能判断云端是否调用、是否成功、哪部分未采用。
5. 模型输入混入多条旧规则预警和确认，事实数量多而角色不清。仅有事实集合不等于模型理解了“当前”“历史”“已确认”。
6. 过去测试偏重拒绝攻击，没有把实际 qwen-plus 在常见用户问题下输出可用分析作为最终门槛。

## 借鉴来源和复用选择

### Spring AI 的结构化输出

已核验项目使用的 v1.1.8 源码具备 BeanOutputConverter，可从 Java 类型生成 schema 并转换模型输出。ResponseFormat 支持 JSON_OBJECT 和 JSON_SCHEMA。复用当前 ChatClient、OpenAI-compatible adapter、预算和取消机制，不手写另一套厂商 SDK。

- https://github.com/spring-projects/spring-ai/blob/v1.1.8/spring-ai-model/src/main/java/org/springframework/ai/converter/BeanOutputConverter.java
- https://github.com/spring-projects/spring-ai/blob/v1.1.8/models/spring-ai-openai/src/main/java/org/springframework/ai/openai/api/ResponseFormat.java
- https://github.com/tzolov/spring-ai-structured-output-demo

官方示例用于理解转换器使用，不直接复制它的旧依赖配置。Spring AI 新版 StructuredOutputValidationAdvisor 不能未经版本核验就照搬到1.1.8，本批不为它升级框架。

### Azure Samples 的答案和来源呈现

借鉴其先取得上下文、再生成答案、在界面呈现引用和支持材料的组织方式。只借鉴交互与引用边界，不引入 Azure Search、向量数据库、部署平台或其整套 RAG 架构。

- https://github.com/Azure-Samples/azure-search-openai-demo/blob/main/docs/architecture.md

### 百炼结构化输出

JSON Object 仅保证 JSON 格式，不保证字段合同或事实正确；严格 JSON Schema 依赖具体模型支持。保持用户现有地域、endpoint和qwen-plus配置，核实实际模型能力后选择模式，不因示例而换endpoint或模型。JSON Object配合BeanOutputConverter和应用检查可作为兼容基线。

- https://help.aliyun.com/zh/model-studio/qwen-structured-output

采用外部代码片段时记录来源及许可证；本方案主要复用已依赖的库API和架构思路。

## 目标流程

用户选择监测项、范围与主题
→ Java形成明确查询计划
→ 现有只读工具取得数据
→ 校验证据并生成精简事实包
→ 云端返回分段自然语言及factIds
→ Java进行结构、引用、关键业务主张检查
→ 分段采用或剔除
→ 保存报告及现有证据快照
→ 页面显示事实、智能分析、建议和依据。

Java提供可核验业务事实，模型提供解释与建议。机器检查不能证明任意自然语言都正确；界面不可把通过结构和数字检查称为语义绝对正确。

## 输入和查询计划

监测项必选，使用现有有效配置的下拉框并允许搜索，避免要求用户记住编号。显示开始/结束日期及本次实际范围。默认范围由后端以该项最新可用业务日期确定，页面可调整，不能暗中固定某年或仅依赖问题文本。

提供快捷主题：综合分析、历史趋势、均值统计、预警与确认。默认综合分析获取范围内日线、对应持久化均值、质量和最新适用预警；用户仍可自由提问。显式日期/主题优先，文字中的明确日期作为兼容输入，冲突时提示用户核对，不悄悄执行另一范围。

有限自然语言同义词统一在一个QueryPlanner处理，例如月均、月均值、月度均值、月度平均。工具选择和事实就绪检查都读取同一个计划，不各自维护关键词列表。跨年查询使用实际起止年，不写死同一年。没有足够历史、来源或成本参数时明确缺失，不用模型补数。

## 精简事实包

继续复用现有EvidencePack和七个只读工具，不新增模型写工具。对云端提供应用层的AnalysisContext投影，保留factId和用途，不发送绝对路径、密钥、manifest内容或无关审计字段。

事实按角色组织：

- scope：itemId、显示名、模式、真实来源、日期范围、数据截至日期、是否模拟。
- latest：最新值、日期、单位及来源。
- trend：Java生成的方向、首尾变化等已有事实；没有的指标不要求模型计算。
- aggregates：grain、周期、均值、校验状态、source/spec等分组身份及各自factIds。
- quality：观测数、缺失、覆盖范围和说明，局部完整不能冒充整个自然月完整。
- currentWarning：最新业务日期、适用规则版本、阈值、基准、当前值、风险和确认信息。
- limitations：缺少数据、样本不足、人工/模拟性质等。

当前预警与历史预警分开。默认只向模型发送当前适用预警；用户请求历史时再附带有限历史摘要。多规则同时适用则明确列出，不能随意挑首条；当前规则无结果时显示数据不足/未评估/未触发的实际状态，不能借旧规则声称当前风险。

证据内部仍保留四态，只有通过现有准入且模式允许的事实进入云端业务上下文。确认时间与业务日期区分；预警没有价格校验状态的字段显示“不适用”，不伪装无效证据。

## 云端输出合同

用普通Java DTO和BeanOutputConverter描述结构，禁止继续要求占位符作文。示意：

```json
{
  "sections": [
    {
      "kind": "TREND",
      "text": "观测区间呈上升趋势，建议关注后续是否延续。",
      "factIds": ["trend-direction-id", "latest-value-id"]
    },
    {
      "kind": "WARNING",
      "text": "该预警已经确认，但确认仅表示已知悉，不代表风险解除。",
      "factIds": ["current-risk-id", "current-ack-id"]
    }
  ],
  "recommendations": [
    {
      "text": "后续可继续观察新数据是否维持当前变化方向。",
      "factIds": ["trend-direction-id"]
    }
  ]
}
```

kind仅允许OVERVIEW、TREND、METRICS、WARNING、QUALITY。限制段数、长度和引用数量；系统提示中明确证据是数据、不能覆盖指令。推荐模型解释有限的事实摘要，不逐条复述全部日线。允许正常日期、单位、数字和中文表达，实际业务值建议由事实卡片承载以减少重复。

JSON解析和字段检查不能代替业务检查。不要假设提供者原生schema已验证事实。正常主路径一次云调用；如确有可修复的格式/字段错误，可在同一总预算内最多一次修复请求，附精确错误和同一事实包。网络、认证、计费、容量、超时不做内容修复重试，重试次数与实际费用如实计数。

## 检查与部分采用

结构错误、未知factId、超范围输入、secret或注入风险具有明确拒绝码。证据真实性始终由Java验证，模型不能创建证据。

对事实解读段：

1. 引用必须存在且属于本次可用事实。
2. 检查价格、日期、单位、来源、均值、阈值、风险和确认等关键主张；不能让某个全局数值碰巧存在就放行错误主张。
3. 数字检查允许等价小数、千分位、百分数等合理格式，但必须保持单位与含义；不同日期、不同校验组、不同预警的值不能互换。
4. 段落内引用过宽或关键角色无法对应时，剔除该段或用Java事实句替代，不能声称已经证明语义正确。
5. 对已知的相反趋势、错误风险、把确认解释成风险解除，拒绝该段。
6. 引用存在不等于引用支持正文，事实检查的覆盖范围与剩余局限必须明确。

对建议：允许基于样本的观察建议和不确定表达；不允许把模型猜测的供需、政策、厂家事件作为已发生事实，不生成无依据的目标价、交易或自动调价指令。说明样本与模拟性质不能仅由模型自觉提供，页面由Java固定展示。

段落可以在JSON结构有效后独立处理，不能用宽松字符串截取挽救损坏JSON。被剔除段若被另一段引用或是其必要前提，相关段一并剔除。严重注入、完全不可解析或所有段均不合格才整体回退。报告保留明确的FULL/PARTIAL/NONE采用状态和受控诊断码；PARTIAL不能标成完整云端成功。

## 界面结果

页面从上到下显示：

1. 本次监测项、范围、数据截至日期、模拟/真实来源说明。
2. Java事实卡片：最新值、趋势、各均值分组、当前预警及确认。
3. 云端智能解读：按趋势、统计、预警等主题分段，显示受控引用链接。
4. 观察建议：明确为模型建议，不冒充事实或操作指令。
5. 折叠的依据与执行步骤、完整生成时报告。

无Key或网络失败时，事实卡片正常可用，云端区域显示具体不可用状态及可理解说明。部分采用时提示部分内容未采用，不用一个巨大错误横幅覆盖整个结果。空数据时先明确数据不足，不浪费云调用生成虚假分析。前端仅呈现后端投影，不计算均值、风险、变化率或修复模型结果。

## 实现分工与兼容

建议在现有包内明确六个职责，避免继续把逻辑堆进AgentOrchestrator：QueryPlanner、AnalysisContextAssembler、LLMService adapter、NarrativeValidator、ReportAssembler、现有ReportStore。

先利用另一个窗口现有WarningSummarySelector等修复，不与其竞争覆盖。Spring AI只存在infrastructure adapter，应用层DTO不依赖框架类型。

旧报告V1/V2继续原严格读取，不修改历史内容。新增段落、部分采用状态及检查结论需要新版本报告合同（建议AGENT-REPORT-V3，实施时核对已有版本）；复用V2证据快照机制，不重建一套快照存储。机器检查通过的模型文字应标为智能解读，不能因沿用旧claims字段而声称整段已由Java证明。

新生产入口只使用一种解释合同。旧占位符路径仅为历史解码兼容，不保留两个随意切换的生产提示词。旧安全测试应保留其攻击目的；只因占位符协议退役而不适用的断言，逐项迁移到新合同并说明，不要求新版继续拒绝本应合法的自然语言。

不新增RAG、数据库、Memory、MCP、Python服务、多Agent或写工具。当前任务是基于结构化业务数据的分析助手，不追求任意自主决策。

## 验收门槛

本地自动化同时验证正常输出与攻击，不能只统计拒绝用例。核心数据固定为当前演示文件，保留原始预警与确认：最新25500、日期2026-10-22；两组均值24800.00/23200.00；当前适用custom-r4为23250→25500、5%、HIGH、已确认。模拟性质全程可见。

交付必须满足：

- 原始失败问题不改措辞即可取得月度均值与正确预警。
- 两种合理自然语言写法、同值不同小数位及包含合法日期均可采用。
- 错价、错日期、混组均值、错预警、假来源、未知引用、虚构解除风险被拒绝。
- 一个坏段不丢弃独立的好段，所有坏段或严重错误诚实降级。
- 无Key、超时、取消、无数据保持事实可用和一致持久化。
- 新报告重启可读；正常追加后保持生成时事实；快照篡改仍拒绝。
- Java17、前端测试与build、桌面必要回归通过。

真实qwen-plus验收在当前账号和请求预算获得授权后执行，建议固定6类问题：最新值、趋势、两组月均、预警与确认、用户原始综合问题、数据不足。前5类有事实的问题均应实际得到可采用云端段落，综合问题连续两次验证；不足场景不要求调用云。保留全部首次与修复结果、请求计数、采用状态、延迟及脱敏证据。小样本通过只证明这些演示场景，不宣称模型永不幻觉。

真实云验收是成品门槛，假模型、HTTP200、JSON可解析或Java降级均不能代替它。授权前完成所有不依赖真实计费的工作。

最终构建独立候选Windows包，采用同一份验收数据复测事实、云输出、预警确认和重启。图文报告、视频和源码对应同一commit及包SHA。其余原需求的动态配置、跨年文件查询和精度证据继续补齐，不因Agent通过而自动判整体通过。

## 实施顺序和完成定义

第一步固定现有工作与输入输出合同，第二步完成结构化云输出和段落检查，第三步完成页面与持久化，第四步进行本地回归、经授权的真实云测试及运行包验收。每步围绕同一设计，不再逐条扩充占位符例外。

本批交付物应包含：唯一源码候选、独立运行包、保留现有数据的升级方式、中文演示步骤、原问题的云端成功证据、功能验收图文及已知限制。先实现和自审，再固定候选独立审查；普通样式或文案小问题不触发整项目重审。

成品标准是用户在EXE中选择标的和范围，用日常中文问题取得有事实依据的云端解读；失败可理解、数据可追溯，既有业务流程不退化。不是通过降低检查后把任何模型文字标为可信，也不是继续让Java模板成为几乎唯一可见结果。
